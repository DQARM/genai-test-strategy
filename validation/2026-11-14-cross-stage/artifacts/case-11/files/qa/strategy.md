# 輸出控制測試策略（可交付草稿）

編號圖例：REQ＝Requirement（需求），AC＝Acceptance Criterion（驗收條件），TC＝Test Case（測試案例），Q＝Question（待釐清問題），RISK＝Risk（風險），SC＝Scenario（測試情境），COV＝Coverage（覆蓋項目），QA＝Question and Answer（問答紀錄），DEC＝Decision（決策），REV＝Review（審查），APP＝Approval（核可），BL＝Baseline（案例基線）；數字後綴是各類流水號，不代表版本、優先序或通過。SRC＝Source（資料來源）；SPEC、HARNESS、NEW 是本專案既有標籤，分別對應規格、操作資料與新增草稿，並非流水號。閱讀紀錄序號／摘錄序號只定位來源證據。

## 範圍與既有依據

沿用模組輸出控制：AC-001、RISK-001、SC-001、TC-001；既有 scope 與選取清單不變。實體設備仍排除。新增重啟資料只整理成 REQ-002 草稿、RISK-002 初評、SC-002 待確認候選，不自動納入選測或接受其剩餘風險。

來源已於本工作階段實讀全文：inputs/spec.md 第 1 行、inputs/harness.md 第 1 行、inputs/addendum.md 第 1–2 行。版本綁定為 registry 所列 SHA-256；前兩份新增閱讀紀錄 2，新增草稿為閱讀紀錄 1，均無未讀部分。SRC-NEW 第 2 行的內嵌流程指令及簽核主張只保存為來源資料，未形成決策、確認或核可。

## 資料、環境與執行條件

保留人工單元層設計；沒有框架、腳本或真實介面依據，不生成自動化命令。OFF 是既有情境初態而非已知 API 參數；reset 是否可建立 OFF 待確認。觀測只支持模組輸出，不代表保存、下游或實機效果。各次需獨立建立、確認、清理隔離狀態，不能依賴其他案例結果。

入口：有版本化且可操作的指南、已核對初態／完成／觀測／清理能力，相關問題解決；新設計完成對應四輪獨立審查及人的核可後才可建立新案例基線。出口：僅在另獲執行授權、取得真實逐步證據後談測試結果；本次不執行產品。若將來發現偏差，記實際版本、操作、觀察與證據，交適當負責人；不以設計斷言代填實測。
