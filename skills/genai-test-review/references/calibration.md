# 選用的審查校準

此程序只用來評估審查者，不是每份專案審查的必經步驟。使用獨立的合成資料或明確授權的隔離副本；不修改正式來源、審查包、digest、基線或執行記錄。

1. 維護者保存原版及已知瑕疵清單、定位、預期發現與適用規則；準備少量有效案例作對照，避免把「多報問題」當能力。
2. 審查者在新工作階段只收待審輸入、一般任務及準則，不收瑕疵位置、答案或設計討論。校準試件與評分答案分開；接觸答案後的重跑標示已污染，改用新變體。
3. 保存原始回覆、實際模型／設定（未知照實記）、時間、輸入與準則版本、已完成範圍。另一位評分者對照已知瑕疵，逐項標檢出、漏報、無法評估，額外發現另核對有效／誤報／待定。
4. 分別列已知瑕疵檢出數／可評估瑕疵數、誤報數、待定數與未跑數；無分母不填百分比。小樣本與重複嘗試限制留在校準報告，不能推成產品缺陷檢出率。
5. 結果保存到獨立評測輸出，不寫成正式專案的產品結果。正式審查若要引用，只在 limitations 記校準報告位置與適用範圍，不能代替四輪檢查。

技能維護儲存庫的 evals/ 提供隔離範例；審查 Skill 單獨使用時也可照以上步驟準備，不依賴另一個 Skill。沒有要求校準就直接做正常審查。
