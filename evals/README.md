# Skill 行為評測（維護者用）

這裡的合成資料用於檢查 AI 是否照流程工作，不是產品規格或實測證據。EVAL 為 Evaluation（評測）；case-01 等是此評測集流水號，與專案 TC 無關。工具整合測試及模型行為分開回報。

## 核心集與隔離

suite.json 列八個任務；rubrics.json 保存評分者專用準則。核心涵蓋邊界未決、來源衝突、缺介面、口頭規則、系統品質、第五答先產出、未知歷史時間，以及審查辨識力。只把 stage 生成的個別 task.txt 及同目錄原始文件交給新工作階段；不交 README、rubrics、目的名稱、先前輸出或修正方向。受測模型先看答案、同一對話反覆修到通過或得知缺陷位置時，標 contamination，不算乾淨的首次評測。

使用實際已安裝／本次修改的技能目錄，不複製一個假安裝。工具不呼叫模型、不操作產品、不安裝 Skill、不建立 Git 專案，也不宣稱自動判斷語意。

## 執行 SOP

1. 執行 `python evals/evaluate.py stage --out /新的暫存目錄 --strategy /設計Skill目錄 --review /審查Skill目錄`。輸出目錄必須不存在；可以 `--cases case-01 case-05` 選受影響情境。工具記輸入及技能檔案指紋，只複製題目，不複製評分答案。
2. 每個任務開新的模型對話／授權代理，給該任務的 task.txt 與原始資料，保存原始回覆為 responses/case-01.md 等對應檔案；工具軌跡可另外保存。按各任務原指令完成，不提供預期答案、評測目的或解題提示。
3. 評分者這時才讀 rubrics.json，逐項核對原始回覆。編輯 grading/case-01.json 等對應檔案 的 grader、model、settings、contamination 及各 check：status 為 pass／fail／unassessed，附逐字 evidence 與 reason；未看到的行為不能猜 pass。metadata 未知用 unknown，不杜撰模型名。所有 pass／fail 都要有原始回覆可核對的摘錄；摘錄存在只驗證可追溯，不證明評分正確。
4. 執行 `python evals/evaluate.py score /暫存目錄`，只檢查輸入與結果結構並統計人工／評分者判斷。沒有 transcript 或尚未評分為 NOT_RUN／INCOMPLETE，不能報整套通過；污染另計。輸出含全部核心集與本次選取的分母。
5. 保存 run.json、responses/、grading/ 及工具結果；記實際版本、模型、設定、時間與限制。真實輸出不可改寫成理想答案。版本差異或失敗需修正後，另開新執行目錄；重要失敗加新的保留變體，避免只記住固定答案。

## 何時重跑

修改 Skill／reference 的行為規則時跑受影響任務；初始化、訪談、判準、來源權威、審查或共同契約的重大改動跑完整核心集。純錯字／連結修正做靜態檢查並記未跑原因。沒有可用模型或不能隔離時明說未跑，不以工具測試代替。單次通過不代表所有模型穩定通過；跨模型或重複次數由維護者按成本選擇並完整回報，不能只挑最好的一次。

## 選用審查校準

case-08 同時提供兩個已知問題及一個有效對照。先按正常審查完成，再由評分者核對 rubrics；記兩個已知問題的檢出／漏報、額外有效發現、誤報與待定，不能將所有額外發現一律當誤報。需要百分比時提供明確分母；沒有完整核對時保留未知。可換新變體／不同模型比較，但不向審查者洩漏答案。不往正式審查包或基線埋錯，也不把這裡的分數當產品測試通過率。
