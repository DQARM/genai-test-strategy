# 讀完來源後，先整理規格缺口

這是設計端的靜態分析；不是產品執行，也不是案例的四輪獨立審查。不新增第三個 Skill。

## 先分析，再決定要問誰

1. 沿用本輪範圍，按 source-reading.md 實際讀相關正文、圖表、變更與共通限制，記已讀／未讀範圍。來源已有有效答案就整理引用，不要求使用者再說一次。
2. 批次找出會產生不同實作或 Expected 的分歧，以下表選適用項目。合併同一個決策問題，不把每項檢查都變成問題。
3. 查現有 `registry.questions`、決策與更正鏈，沿用原編號；新問題續號。分開「文件缺口」「AI 建議」「已確認規則」，不能自行採用建議選項。
4. 按本輪影響排序，保留責任人／未指派、確認時點、影響及阻塞範圍。先列短摘要；完整問題交接單供非同步閱讀，不能一次貼整份問卷要求回答。
5. 有決策人在場且允許續問時，只問當下最重要的一題，沿用 [workflow.md 的續問狀態](workflow.md#統整與續問)。PM／工程不在場、使用者選先產出或要求非同步時，匯出問題單並繼續不受影響的策略與案例；未知規則或介面只阻塞相關項目。

批次分析、登錄及匯出**不算已提問**，不新增假 QA 紀錄；計數依 workflow.md。真正向人提出需求決策問題才計數；收到非同步回覆時如實保存提問／原話、回答者與時間，不偽造對話回合。

## 缺口分類

| category | 檢查焦點 | 交接問題應說清楚什麼 |
|---|---|---|
| ambiguity | 「快速」「正常」「必要時」等多種解讀 | 哪個條件／量測／結果尚不能判定 |
| exception | 逾時、失敗、部分完成、復原 | 發生點、目前承諾與尚缺的處置 |
| boundary | 等號、單位、範圍、精度、時間起算 | 哪條界線會改變分區或判定；不猜步距 |
| assumption | 隱含前提、外部依賴、前後狀態 | 哪個假設尚未有來源，不把它當事實 |
| conflict | 版本／圖文／角色說法互相衝突 | 並列兩份來源及位置，請確認適用條件或權威 |
| testability | 無法建立初態、刺激、觀測或重置 | 缺哪個操作／觀測能力，建議轉工程或測試負責人 |
| role-permission | 誰可執行、資源歸屬、授權失效 | 哪個角色在何狀態對哪個資源有待決行為 |
| other | 本專案其他重要缺口 | 具體分歧、後果與所需決策 |

## 單一資料來源

Q＝Question（待釐清問題）、SRC＝Source（資料來源）、QA＝Question and Answer（原始問答）、DEC＝Decision（決策）；數字後綴都是各類流水號，不代表優先度、版本或核可。

沿用 `registry.questions` 原欄位，選填：

- `category`：上表記錄值。
- `urgency`：blocking／important／later／untriaged。是問題處理急迫性，不是風險嚴重度；缺欄位顯示未分級。`blocks` 與 `impact_ids` 仍指定實際阻塞階段／範圍，不由 urgency 自動推導。
- `source_refs` 與 `source_citations`：問題來自哪些實際讀過的版本及定位摘錄；衝突兩邊都列。口頭問題連原始 QA，不假造文件。
- `analysis`：不同回答如何影響實作、判準、風險或案例。
- `suggested_owner`：建議轉交的角色；不等於已指派或對方已承諾。原 `owner` 未知仍填 `unassigned`。
- `options`：選填的中性文字選項，每項說明影響；全部都是建議，回答者可提出其他方案。

原 `status` 仍為 open／deferred／resolved，deferred 仍未解決。不能用排序、匯出或沉默把問題改 resolved。

## 交付與接回

使用支援 export-questions 的專案工具；舊版依 [migration.md](migration.md) 升級。`python qa/tools/qa_project.py export-questions .` 產生 `qa/questions.md`；`render` 也更新它，HTML 的其他成果提供連結。工具只整理已登錄內容，不自動閱讀文件或發現語意缺口。

問題單含版本、分類、分歧、來源／摘錄、責任人、時點、影響、建議選項與空白填答欄。匯出不改原始記錄、session、題數或設計 digest。請將填答另存副本，避免下次 render 覆蓋回覆；未附來源原檔時，相對連結在別台電腦可能無法開啟。

收到填答後，保存原件作證據，逐項核對回答與當時問題是否相符、是否仍對應目前版本。依 interview-records.md 記原話／完整度，真正決策才形成 DEC、更新規則與 resolved。模糊或矛盾回答保留問題；決策者未在場時不把 QA 的推測寫成 PM 已確認。更新受影響案例、版本與審查交接，不重編舊 ID。
