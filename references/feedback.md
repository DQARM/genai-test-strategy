# 實測回饋與少量度量

只在收到實際執行／缺陷資料或使用者要求檢視成效時使用。保持生成、審查與實測的區分；沒有證據就記未知，不以設計品質代替產品結果。

## 回饋到風險與回歸

1. 保留缺陷原文、受測版本、案例／RUN、操作、環境及證據；區分已重現缺陷、尚待確認的回報、測試或環境問題。沒有實測的 AI Finding 不登錄為已發生的產品缺陷。
2. 按 source-reading.md 登錄並實讀 experience 來源，引用具體位置及適用條件，沿用既有來源／風險與修訂關係。經驗支持失效假說，不直接成為 Expected。
3. 重看相關風險的 likelihood／不確定性、影響範圍及現有控制，提出新初評和理由；有實際次數、暴露量及觀測期間才談頻率，單次缺陷不直接換成機率。severity 依後果重評，不隨發現次數自動升降。
4. 依已確認規則更新案例與 COV，保留舊基線及執行快照；沒有原規則就新增 Q。修復後重跑需新執行證據，不能用已改程式或已關閉 bug 代替。
5. 新的取捨需要人的真實決策；停止訪談的狀態不因收到缺陷而自動解除。由 session 記下一個動作及回訪條件。

## 可選度量

按需要選少量，記定義、期間、版本、分子／分母、資料來源與限制，可放 qa/plan.md 的回顧段；未知或零分母用 null／未知，不補估值。

| 度量 | 可用來看什麼／不可如何解讀 |
|---|---|
| 無依據 Expected 次數、停止指示違反次數 | AI 行為的具體違規；需核對原文與實際回覆，不能只看關鍵字 |
| 已知缺口檢出與誤報 | 用獨立評測情境及經核對發現計數；重複發現不多算，未判定項目另列 |
| 每筆新確認規則的實質提問數 | 只在範圍、粒度相近時輔助檢視負擔；一題可支持多條規則，題數越少不保證品質越好 |
| 人確認的有效 Finding 與處理情況 | 區分嚴重度、重複、駁回及待釐清，不以 AI 產生總數作績效 |
| 測後／發布後逃逸缺陷 | 綁版本、觀測期間及原已測範圍；新範圍或尚未確認的問題分開，尚無觀察資料不是零 |

維護 Skill 的行為評測由 evals/README.md 定義；不要求每位專案使用者建評測平台或 CI/CD。
