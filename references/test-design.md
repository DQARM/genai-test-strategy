# 從驗收條件推導測試

AC＝Acceptance Criterion（驗收條件）；COV 取自 Coverage（覆蓋），表示一個覆蓋項目；TC＝Test Case（測試案例）。編號後綴是類別流水號，不是優先度或結果。

## 先選方法，再寫案例

沿用已選範圍、風險與人的決策。AI 負責分析、列出項目、填記錄及設計案例；人只處理真正未決的產品行為或重要取捨。方法選擇與整理本身不增加訪談題數。依據充分時，呈現簡短理由後直接繼續，不另設逐項核可。

1. 把已確認 AC 的條件、輸入域、輸出、時間及狀態列清楚，保留相關共用判準。草稿、未決內容與操作介面分開。
2. 依下表選最有價值的方法；不是對每個 AC 套用全部方法。先建立簡單的分區、條件表或狀態模型，缺條件就標缺口。
3. 列出方法產生的覆蓋項目：分區、邊界及相鄰值、可行條件組合、狀態／轉移或具體情境。記錄採用方法、規則、描述、保留或暫緩及理由。
4. 在既定風險取捨內保留項目；超出授權的新取捨標為建議，不代替人接受風險。待確認規則不寫成 Expected。
5. 為保留項目選資料、初態及真實操作，建立獨立可重跑的案例；讓產品斷言同時連到 AC 與 COV。多個項目可由同一案例承接，但每項都要有實質輸入與觀察。
6. 審查項目清單本身是否完整、案例是否真正承接，及未測部分留下什麼風險。連結完整不等於方法正確，也不等於已實測。

## 方法選擇

| 已確認規則的特徵 | 方法／記錄值 | 應列的覆蓋項目與注意事項 |
|---|---|---|
| 同類輸入應有相同行為 | 等價分割 `equivalence` | 合法／不合法分區及代表值；每個分區都須有行為依據。未知錯誤處理先探索或列問題。 |
| 有順序、門檻或區間 | 二值邊界 `boundary-2` | 每個已選邊界值及相鄰分區最近值；先確認型別、單位、解析度及等號語意。 |
| 邊界風險高、需再查同側鄰值 | 三值邊界 `boundary-3` | 每個邊界值與兩側鄰值；去除重複後列出完整集合。 |
| 多項條件共同決定結果 | 決策表 `decision-table` | 可行條件組合、結果與不適用條件；每一保留欄是項目。刪除不可行組合須有依據。 |
| 相同事件會因初態不同而有不同結果 | 狀態轉移 `state-transition` | 初態、事件／守衛條件、終態及輸出。說明選有效轉移或有效加無效轉移；無效轉移的拒絕行為也須有判準。 |
| 設定維度多且交互作用是風險 | 成對組合 `pairwise` | 已確認的因子、值域、限制及可行值對。成對不代表涵蓋三項以上交互作用；已知高風險組合另列。 |
| 失效涉及三個以上因子或混合強度 | 組合測試 `combinatorial` | 記強度 t、因子／值域／限制及具體 t 元組；不宣稱 pairwise 已涵蓋高階交互作用。 |
| 跨角色、流程、介面或端到端承諾 | 情境式 `scenario` | 特定流程、初態、檢查點與替代路徑，分清各層證據。 |
| 缺陷歷史或測試經驗指出可疑情境 | 經驗式 `experience` | 記錄線索來源與風險；有已確認判準才形成判定式案例，否則使用探索任務。 |
| 有具體常見錯誤機制可檢驗 | 錯誤推測 `error-guessing` | 寫失效假說、觸發條件及線索，不只寫「異常測試」；Expected 仍需已確認規則。 |
| 同一資料經多階段／角色／副本處理 | 資料生命週期 `data-lifecycle` | 列資料狀態、跨階段轉移及檢查點，含適用的更新、刪除、復原及引用關係。 |

例：**僅作數學示意**，已確認整數、步距 1，分區是 `x < 50` 與 `x >= 50`。交界兩個邊界值為 49、50；二值邊界的去重集合為 49、50，三值為 48、49、50、51。若只確認「≥50 告警」，不能由此推論「<50 不告警」。若是連續量測且解析度未知，先保留符號描述，不自行採用 ±0.1。這些數字不是新專案預設值。

## 讓風險決定深度

依 [failure-modes.md](failure-modes.md) 找到失效機制，再選方法、層級、深度與證據。嚴重度、可能性、不確定性及實機成本是選擇依據；不要機械套用「高風險＝三值邊界」或以低測試成本降低危害等級。

| 失效機制／尚缺證據 | 可考慮的深度 | 應交代的成本與剩餘風險 |
|---|---|---|
| 比較運算子錯誤、精度或等號疑慮 | 有型別／解析度依據的邊界集合，必要時三值 | 鄰值可否注入／量測；沒有解析度不猜小數 |
| 單一步正常，特定前序後才失敗 | 有效轉移之外增加相關轉移對或較長序列 | 序列建立／重置成本；未測序列明列 |
| 三個條件同時成立才觸發 | 該組合直接列項，或 t≥3／混合強度組合 | 可行組合數、限制及尚未覆蓋的交互作用 |
| 逾時／斷電造成部分完成 | 對關鍵階段注入失敗，核對資料、恢復與下游 | 注入授權、設備風險、回復條件；缺行為規則列問題 |
| 高危害但規格／觀測不足 | 優先補規格與觀測，先交可行探索或受阻草稿 | 不能因只剩少量可執行步驟就宣稱充分驗證 |

在策略記「風險 → 失效機制 → 方法／深度 → 保留項目／證據 → 成本／未測部分」，案例只負責落實選定項目，不在撰寫中暗改取捨。方法分析不額外索取例行核可；需要新的產品規則或風險接受時才沿用訪談節奏取得真實決策。

## 深入方法時才讀

### 狀態與序列

`state-transition` 的 description 說明選用的準則及模型位置：只到過所有狀態、涵蓋所有有效轉移、嘗試有效及無效轉移，或針對前序敏感的**相鄰兩個轉移**。轉移對不是同時測兩個獨立事件；必須連續、可行，包含中間狀態及守衛條件。

例如已確認模型 A → B → C 與 A → B → A，單獨測 A → B、B → C、B → A 不一定證明兩條連續序列都正確。列出各項序列、建立初態、各步觀測及重置。這是方法示意，A／B／C 是狀態標籤，不是產品預設狀態。無效轉移與更長序列關注不同缺陷，不能把它們當單一線性等級；未知拒絕行為列問題。

### 組合與約束

明列因子、值域、強度 t、可行性限制與來源。t 表示同時覆蓋幾個因子的值組合；pairwise 即 t=2。已知失效取決於權限、狀態及連線三者，不能只以「已有 pairwise」結案；另列三因子組合或選相應強度。高強度不是所有專案必用。

每個保留項目指明實際組合；生成工具若有使用，保存版本、模型、種子（有才記）、輸出與覆蓋核對。套用約束後重新核對**可延伸為完整合法設定**的 t 元組；不能先產生無約束組合再刪列，就聲稱仍完整覆蓋。未確認限制不可當不可行條件刪除。手動小表同樣適用，不強制安裝組合工具。

### 決策表縮減

條件與結果先對應規則。只有有依據證明某條件不影響同一組結果時，才合併成 don't care（不影響結果）；保留原列到合併列的映射。不可行組合附約束來源；未知結果保留待決，不可當不可行或空白＝不執行。縮減後核對原先所有可行組合仍有承接，尤其角色與資源邊界不能因結果字面相同而遺失適用條件。

### 錯誤推測與資料生命週期

錯誤推測先寫可反駁的假說，例如「相同請求重送可能造成重複處理」，引用本專案缺陷／介面線索，再找已確認判準與注入點；不以經驗本身證明 Expected。

生命週期從本產品實際資料狀態挑選：建立 → 修改／同步 → 使用／匯出 → 封存／刪除 → 還原。加上適用的取消、部分失敗、併發、引用及快取／備份，不強迫每案走完整流程。各步區分畫面、持久化、副本與下游；規格未承諾的刪除傳播、保留期或還原效果先列缺口。

## 記錄與檢查

`registry.coverage_items` 每項使用 records.md 的契約。案例 `coverage_ids` 宣告關聯；有產品斷言的 `checks[].coverage_ids` 指明實際承接項目，`rule_refs` 仍引用已確認 AC，不能用 COV 取代規則。

工具政策 `project.design_policy = "coverage-items-v1"`：

- 每個已選 AC 至少有一個保留 COV，避免清空清單就通過。
- 該 AC 的所有保留 COV 都有已選案例的斷言承接；只在案例頂端掛 ID 不足夠。
- 斷言引用的 COV 必須屬於該案例，並有其所有 AC 作為判準依據。
- 暫緩 COV 留下原因、剩餘風險；建立基線前須連到實際人的取捨決策。同一決策可以涵蓋多項，不逐項重問。
- 原有 AC、風險、情境覆蓋與四輪審查仍適用；探索任務不能補足正式案例缺口。

工具驗證結構和引用，無法證明自由文字的模型完整、輸入真的落在宣稱分區，或斷言符合規則。審查仍要核對這些語意。覆蓋表標示的是**設計承接**；執行覆蓋必須另以相符版本的實際步驟、結果與證據判斷。
