# 品質特性與系統風險檢視

在風險策略階段，先讀本輪目標、產品／介面、部署環境與約束，再由 AI 批次篩選下表；每項簡記適用、不適用或待確認及理由。這是分析狀態，不是人的範圍決策；適用也不代表本輪全部要測。沿用已選範圍，重大遺漏列待辦及取捨，不自行擴張 scope。

## 品質特性

以下是參考 ISO/IEC 25010:2023 產品品質模型的實務提示，不是標準條文重製、合規清單或預設驗收規格。功能適合性也列入以連回既有 AC；符合性等跨特性問題另於下節檢視。

| 檢視面向 | 依本專案可分析的失效與證據 |
|---|---|
| 功能適合性 functional suitability | 必要工作是否缺漏、結果是否正確；連回既有 AC，避免另建重複規則 |
| 效能效率 performance efficiency | 負載、容量、資源及回應時間；記工作量、量測位置、統計方式與依據 |
| 相容性 compatibility | 共存與互通、協定／格式／版本配對；核對雙方收發及實際效果 |
| 互動能力 interaction capability | 使用者能否理解、操作、辨識錯誤及恢復；依真實角色與使用情境觀察 |
| 可靠性 reliability | 長時間運作、故障、可用性與恢復；區分服務恢復與資料完整性 |
| 資訊安全 security | 身分、權限、資料保護與攻擊面；依授權環境與已確認安全需求設計 |
| 可維護性 maintainability | 診斷、修改影響、可測試性；例如現有日誌是否能定位失效，不假造內部介面 |
| 彈性 flexibility | 配置、部署、適應及擴充；檢視切換後的相依狀態與資源限制 |
| 安全性 safety | 故障是否危及人、設備或環境，是否有適用的安全狀態與告警要求；無情境依據不誇大危害 |

安全性與資訊安全分開評估。不因某面向未知就列不適用，也不因相關程式不可見就免評；可列黑箱觀測或取證缺口。

## 系統、設備及通訊產品

對這類產品，另外明列以下五項的適用性；它們可以跨越上表多個品質特性，不需重複建立風險。

| 項目 | 必要的分析條件與缺口 |
|---|---|
| 符合性 | 哪一份適用規範、版本、profile／選配及條款；沒有採納依據不假稱符合標準 |
| 互通性 | 真實對端、硬體／韌體／協定版本組合及能力協商；單端成功不能代替互通 |
| 強健性 | 異常／中斷／資源不足的故障模型、觀測與恢復；實際注入依授權與可復原條件執行 |
| 長時間穩定性 | 使用型態、負載、運作時長、累積資源、事件及中斷；缺時長／退化判準就列問題，不套 24／72 小時 |
| 時序 | 觸發與觀測點、事件順序、時鐘基準、同步、解析度及量測誤差；缺時間窗／容差不填任意毫秒值 |

## 從檢視到案例

1. 在 qa/strategy.md 保存精簡表：面向｜適用性與理由／來源｜本輪選取／待取捨｜風險／待釐清連結｜方法及觀測需求。對話模式用同樣內容，明說未保存；已有 table 只更新差異。
2. 有失效線索就沿用既有 RISK；缺判準、負載、時長、介面或量測能力就連 Q。只有改變驗收、重大風險或本輪取捨的分歧才依原訪談狀態問人；已選先產出時只列待辦。
3. 判準足夠且屬已選範圍時，依 test-design.md 列 COV，寫具體輸入、初態、步驟及斷言；判準不足保留 blocked／探索適用性，不用品質清單直接生成 Expected。
4. 真機昂貴時優先評估手動、既有量測及可用模擬的成本。寫明它們可支持的結論，設備回覆、物理效果及模擬證據分開。

不新增必填 registry 欄位；品質目標沿用 project.quality_goals，問題、風險、COV 仍用既有契約。策略本就在設計 digest 範圍，改動照常綁定新版本；舊資料沒有檢視表不回寫歷史。

參考：[ISO/IEC 25010:2023 官方簡介](https://www.iso.org/standard/78176.html)。產品門檻與適用規範仍由本專案資料及決策決定。
