# 審查交接、修正與核可

此文件供 genai-test-strategy 準備及接回審查；四輪的逐項審查準則由獨立的 genai-test-review 維護。兩個 Skill 共用同一專案及資料契約，審查端只新增審查紀錄，設計端負責規格／案例修正及核可基線。

## 設計端交出待審版本

1. 完成本輪能交付的案例與結構檢查，保留已選範圍、必要依賴及仍受阻內容；不為方便審查移除範圍或未決事項。
2. 取得完整設計 digest，用新 ID 執行 review-pack。工具 1.4.0 的 PROMPT 會指向 genai-test-review；舊工具的 packet 仍可使用，手動在新工作階段指明使用審查 Skill 即可，不需要重建專案。
3. 一併提供 packet、PROMPT 與被引用的已確認規格、操作文件、決策證據及版本。pack 不自動複製全部來源，不能假稱只有 packet 就足夠。排除無關產碼與案例生成對話，不以現行程式或介面定義 Expected。
4. 審查以四種檢查為範圍：規格追溯、可執行且可判定、已選範圍覆蓋、一致性。取得內容及原文，不只檢查引用欄位存在。

新工作階段可貼（路徑及 ID 換成本次實際值）：

```text
請使用 genai-test-review，讀取本專案 qa/review-packs/REV-001/packet.json 與 PROMPT.md。
沿用指定範圍與版本，重新讀取必要的規格、決策與操作依據。
只留下具體發現與修正建議，不修改產品規則或案例，不重新初始化專案。
```

REV 取自 Review（審查），001 是這類紀錄的流水號；交接包與審查記錄所在目錄不同，使用時確認各自唯一名稱。尚未安裝新 Skill 時，提供其安裝入口或交由人按已選四項審查；不假稱已安裝、不偷偷在原對話把自查當獨立審查。審查 Skill 的 GitHub 入口為 [genai-test-review](https://github.com/DQARM/genai-test-strategy/tree/dev/skills/genai-test-review)。

## 獨立性與版本

只有真實新工作階段重新載入依據才標 fresh-session；原對話自查標 same-session，人實際審查才標 human。換模型可降低部分共同偏誤但不保證獨立判準；同源假設即使在程式與案例中一致，仍需查明規格支持。沒有獲准或環境不支援時不自行建立代理，改交新對話包。

審查版本以完整設計 artifact_digest 為準；packet 的 review_input 可能過濾來源種類，不能對該子集另算 digest 冒充原始完整版本。來源 hash 也須與實際文件相符。舊版審查只適用該版，來源不可讀或未檢完全部範圍時，對應輪次不能列完成。

## 設計端接回發現

讀取實際 review 檔的版本、完成輪次、limitations 與 findings；不要只看「通過」文字。每項 Finding（發現）應有案例／規則、具體問題、證據及修正建議。依人的實際處置修正、合併、暫緩、待釐清、接受剩餘風險或有依據駁回，不能代填核可。

沿用原 session 的焦點、累計題數、本批額度、續問狀態與選擇依據。已確認答案不重問；只有本批仍可提問且確有必要時才釐清。等待選擇時先依原檢查點取得續問選擇，已選先產出或明訂總上限已到時只列待辦，不藉修正重新訪談。操作缺口先查文件或交合適負責人。

產品規則、範圍或案例一旦修改，更新 revision／supersedes、相關覆蓋項目、進度及閱讀網頁，再取得新 digest 交回重審。保留舊 review；記錄發現與修正的關聯，不改舊 digest。只改 Finding 為 fixed 不代表新內容已審查。

## 核可基線

正式基線需要目前完整設計的四輪獨立審查、發現已有人處置，以及人對目前內容的明確核可。使用者已明確核可相同內容時不重問；沒有實際核可不得代填。

新基線使用 coverage-items-v1：每個已選 AC（Acceptance Criterion，驗收條件）有保留 COV（取自 Coverage，覆蓋項目），全部保留項目有已選案例斷言；暫緩項目具有人決策與剩餘風險，同時保留 AC／風險／情境的檢查。舊專案依 test-design.md 補齊資料，新 digest 重審；舊基線與執行快照不改寫。

工具 1.5.0 的新基線另依 [risk-assessment.md](risk-assessment.md) 採 requirement-risk-v1：本輪涉及需求的評估已確認、風險分級有依據、已選風險有案例，其他關聯風險有暫緩決策。全專案未選需求仍可未評估，不因此重啟訪談。

工具只能驗證結構，不能證明規格、覆蓋模型及自由文字正確。核可記錄與 baseline 由設計端依 [records.md](records.md#審查核可) 及 [local-versioning.md](local-versioning.md) 建立；案例基線不是產品放行。

工具 1.5.0 的 risk_evidence_source_ids 保留風險初評引用的觀察資料；這些資料只支持危害／可能性分析，不能取代已確認的產品 Expected。未引用的任意現況觀察仍不加入審查包。
