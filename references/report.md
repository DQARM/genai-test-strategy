# 來源與測試案例閱讀網頁

保留既有成果，將 `qa/report.html` 作為方便閱讀的入口；不要求使用者先架設網站或連上 Git server。HTML（HyperText Markup Language，超文字標記語言）是瀏覽器可直接開啟的網頁格式。

## 產生方式

使用支援目前報告功能的專案工具；舊版依 [migration.md](migration.md) 更新。從專案根目錄執行：

```bash
python qa/tools/qa_project.py check .
python qa/tools/qa_project.py render .
```

check 有缺口時如實處理；可先產生帶缺口的閱讀草稿，不能因此宣稱規格有效或案例可執行。render 同時保留原有規格、案例、追溯 Markdown 與編號字典，再生成網頁；不另建立一份手動維護的引用表。

覆蓋項目與探索任務的定義見 [test-design.md](test-design.md)；舊資料相容性見 [migration.md](migration.md)。

## 閱讀內容

- **規格問題交接：** qa/questions.md 依原 questions 產生排序、影響、責任／時點、來源定位及待填答欄；HTML 的其他成果提供連結。問題詳情可直接點已登錄來源與摘錄。批次分析／匯出不代表已問或已決策。跨領域風險明列來源與評估，不要求補假需求。

- **來源閱讀證據：** 另列閱讀狀態、索引／正文、已讀範圍、未讀部分、限制、版本及每次定位摘錄。缺歷史紀錄不等於未讀；來源 confirmed 不等於已讀。案例與引用物件能點到指定閱讀的指定摘錄，摘錄可反查案例；錯誤／過期引用明列。另生成 `qa/source-reading.md`。依 [source-reading.md](source-reading.md) 先實際閱讀並登錄，render 不自行解析原檔或補造內容。

- **問答紀錄：** QA＝Question and Answer（問答紀錄；數字後綴為流水號）。顯示原始問題／選項、原始回答、獨立 AI 解讀、完整度、回答狀態與更正鏈；由案例、需求、風險及決策雙向點閱。另產生 qa/interview.md。舊資料只剩摘要會標示缺原文，未登錄不代表沒有訪談；問答存在不等於規則已確認。

- **來源清單與詳情：** SRC＝Source（資料來源），列出來源編號、檔名／標題、版本、定位、類型、確認狀態及檔案指紋；可看登錄摘錄、開啟專案內原檔、反查引用案例。沒有案例引用的來源也列出。
- **案例清單與詳情：** TC＝Test Case（測試案例），列出所有案例、本輪選取狀態、前置條件、資料、完整步驟、預期結果、判準、觀測／時機、證據需求與清理方式；點來源編號跳到同頁來源詳情。
- **引用路徑：** AC＝Acceptance Criterion（驗收條件）、REQ＝Requirement（需求）。依已登錄關係呈現 TC → AC → SRC 或 TC → AC → REQ → SRC。步驟斷言與案例僅宣告的關聯分開標示；操作／觀測與自動化介面、以來源編號明確登錄的資料依據另標用途，不能當成產品規則。
- **其他成果：** 已登錄需求、驗收條件、DEC＝Decision（決策）、風險、情境、待確認問題均可點閱；原策略、計畫、進度文字亦保留。頁面附編號字典，數字後綴為類別流水號，其他後綴沿用專案標籤。
- **需求風險評估：** 每個需求顯示未評估／已有初評／已確認及評估過期狀態，列出直接關聯風險、後果、嚴重度、可能性、測試優先序與案例。需求與風險可雙向點閱；各項理由與來源在詳情，分級準則另列。缺關聯風險列「未對應需求」，未評估不當成沒有風險，unknown 不當最低等級。同步產生 qa/risks.md，無須維護第二份資料表。
- **設計覆蓋：** COV 取自 Coverage（覆蓋項目），顯示方法、描述、AC、已選案例的斷言引用；詳情可點回 AC／案例與取捨決策，暫緩項目保留剩餘風險。AC 也可反查 COV，新增 `qa/test-design.md` 保存同一資料的 Markdown 視圖。工具不從連結推算實際執行覆蓋率。
- **探索任務：** EXP 取自 Exploration（探索），列出目的、範圍、時間、操作、觀察及停止條件，與來源雙向連結。這是計畫，實際紀錄另存在 evidence，不計入正式案例承接。
- **判準與線索：** 顯示共用判準的適用條件、推導關係、限制與確認決策；經驗來源及比較參考資料分別標示用途，不混成產品應然規則。

雙向連結僅代表登錄關係。沒有明確引用時不按文字相似度或現行程式行為補關係；規則若只由人的決策支持，保留決策連結，不編造 SRC。找不到引用對象時顯示「未登錄」；檔案遺失／不安全路徑不產生原檔連結；指紋與登錄值不同時標示來源已變更。這些不會自動改動已確認規則或舊基線。

## 分享與更新

- 直接用瀏覽器開啟網頁，頁內連結與完整案例不需伺服器或外部套件。可用瀏覽器的尋找功能搜尋編號或文字。
- 單獨分享 HTML 可以點閱頁內已收錄的資料；要開啟來源原檔，需一併保留專案相對目錄及所需文件。網頁不自動嵌入所有來源檔的完整內容。
- 修改 registry 或案例後重新 render；不要直接改生成的 HTML。頁面標示產生時間，代表該次資料快照。
- 這是設計與已登錄結果的閱讀報告；生成不等於審查通過、人工核可、實際執行或產品放行。實測原始資料仍在 runs／evidence，不能把 Expected 當 Actual。
- 沒有使用者專案資料而需要展示時，只使用明確標示的虛構示範資料；不得冒充使用者的規格、核可或測試結果。示範資料不寫入新專案預設內容。


## 版本化審查與實測結果

工具 1.10.0 起另讀 reviews／approvals／baselines／runs。每筆列完整 artifact_digest，與目前完整設計比對為目前／歷史／未知；只按明確案例關聯雙向連結。舊審查若未列 checked_case_ids，只能連其 finding.case_ids，不借用目前範圍假造完整審查覆蓋。

審查列實際輪次、獨立性、限制及 Finding 原處置；fixed 不等於新版本重審。基線列凍結案例、核可與審查；它是案例基線，不是產品放行。

RUN 詳情並排顯示凍結步驟／Expected 與該次 Actual、執行時間、狀態、證據連結及更正歷史。案例內容相同與完整設計版本相同分開比對；舊版 PASS 不套用新版，不同 SUT build／環境不合併成一個通過率。進行中顯示「登錄中」，舊紀錄未填的 metadata 保留未知。

缺檔、錯誤 JSON、不安全路徑、證據指紋或快照不符要可見，不靜默排除；報告不改原始結果、基線或審查。單獨分享 HTML 無法開啟未一併攜帶的外部證據，保留相對目錄。統計卡片只計已登錄筆數，不產生放行紅綠燈。
