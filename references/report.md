# 來源與測試案例閱讀網頁

保留既有成果，將 `qa/report.html` 作為方便閱讀的入口；不要求使用者先架設網站或連上 Git server。HTML（HyperText Markup Language，超文字標記語言）是瀏覽器可直接開啟的網頁格式。

## 產生方式

專案內 `qa/tools/qa_project.py` 需為 1.2.0 或以上；舊版先依 local-versioning.md 更新。從專案根目錄執行：

```bash
python qa/tools/qa_project.py check .
python qa/tools/qa_project.py render .
```

check 有缺口時如實處理；可先產生帶缺口的閱讀草稿，不能因此宣稱規格有效或案例可執行。render 同時保留原有規格、案例、追溯 Markdown 與編號字典，再生成網頁；不另建立一份手動維護的引用表。

## 閱讀內容

- **來源清單與詳情：** SRC＝Source（資料來源），列出來源編號、檔名／標題、版本、定位、類型、確認狀態及檔案指紋；可看登錄摘錄、開啟專案內原檔、反查引用案例。沒有案例引用的來源也列出。
- **案例清單與詳情：** TC＝Test Case（測試案例），列出所有案例、本輪選取狀態、前置條件、資料、完整步驟、預期結果、判準、觀測／時機、證據需求與清理方式；點來源編號跳到同頁來源詳情。
- **引用路徑：** AC＝Acceptance Criterion（驗收條件）、REQ＝Requirement（需求）。依已登錄關係呈現 TC → AC → SRC 或 TC → AC → REQ → SRC。步驟斷言與案例僅宣告的關聯分開標示；操作／觀測與自動化介面、以來源編號明確登錄的資料依據另標用途，不能當成產品規則。
- **其他成果：** 已登錄需求、驗收條件、DEC＝Decision（決策）、風險、情境、待確認問題均可點閱；原策略、計畫、進度文字亦保留。頁面附編號字典，數字後綴為類別流水號，其他後綴沿用專案標籤。

雙向連結僅代表登錄關係。沒有明確引用時不按文字相似度或現行程式行為補關係；規則若只由人的決策支持，保留決策連結，不編造 SRC。找不到引用對象時顯示「未登錄」；檔案遺失／不安全路徑不產生原檔連結；指紋與登錄值不同時標示來源已變更。這些不會自動改動已確認規則或舊基線。

## 分享與更新

- 直接用瀏覽器開啟網頁，頁內連結與完整案例不需伺服器或外部套件。可用瀏覽器的尋找功能搜尋編號或文字。
- 單獨分享 HTML 可以點閱頁內已收錄的資料；要開啟來源原檔，需一併保留專案相對目錄及所需文件。網頁不自動嵌入所有來源檔的完整內容。
- 修改 registry 或案例後重新 render；不要直接改生成的 HTML。頁面標示產生時間，代表該次資料快照。
- 這是設計報告；生成不等於審查通過、人工核可或實際執行。實測仍寫在 runs／evidence，不能把 Expected 當 Actual。
- 沒有使用者專案資料而需要展示時，只使用明確標示的虛構示範資料；不得冒充使用者的規格、核可或測試結果。示範資料不寫入新專案預設內容。
