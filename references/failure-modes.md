# 從失效機制找高價值測試

先讀本輪資料，再用下列方向挑出適用的少數線索。這是 AI 的分析輔助，不是每個專案必填的問卷或正式產品規則。

## 分析單位

以「條件 → 失效機制 → 後果 → 可觀測證據」描述風險，另列來源與不確定性。例如資料有可能重複送達只是風險線索；沒有已確認冪等規則，不能直接斷言必須只處理一次。

| 觀察方向 | 可檢視的失效線索 | 可考慮的驗證與證據 |
|---|---|---|
| 結構／介面 | 格式、單位、版本、責任邊界或上下游假設不同 | 契約／整合情境，對照輸入、輸出及接收端效果 |
| 功能／狀態 | 前一操作殘留、非法轉移、取消未完整回復 | 狀態／轉移對，記初態、事件序列與各步觀測 |
| 資料生命週期 | 建立、更新、同步、匯出、封存、刪除、還原不一致 | 跨階段情境，檢視權限、引用、快取、備份與資料完整性 |
| 平台／環境 | 韌體／硬體版本差異、時鐘、儲存不足、電源或網路中斷 | 已授權的故障注入與復原；記真實設備、時序與量測條件 |
| 操作／角色 | 重複操作、不同使用者接手、授權撤銷競爭 | 角色／資源／狀態組合，核對允許與拒絕判準 |
| 時間／負載 | 事件重排、重試重複、逾時、久置、資源競爭 | 明確時間窗或順序，關聯事件記錄；不先猜等待秒數 |

## 依產品收斂

- 系統／設備：區分命令發出、設備回覆與物理動作；先找可安全建立的初態、量測點及復原方式。真機成本高時先做可行的人工檢查或已確認模擬，但不以模擬結果冒充真機證據。
- 分散式服務／資料：留意部分完成、重送、快取過期、遷移與回復、跨租戶資料及非同步完成；畫面成功不代表落盤或下游成功。
- UI／業務流程：留意返回／取消、跨頁狀態、重複提交、角色交接、失敗後續作；以實際操作指南提供手動步驟。
- 網路／部署：檢視拓樸、配置漂移、重跑／重啟、相依服務與權限；不能用命令 exit code 取代服務行為與安全邊界證據。
- AI／agent 產品才加入非確定性、資料集、工具權限及來源支持等線索；不因使用 GenAI 寫案例，就把其他產品當成 AI 產品。

## 使用團隊經驗

有既有缺陷、事故、常踩坑或編碼限制文件就登錄為 SRC（Source，資料來源；後綴為流水號），以 experience 用途閱讀、定位引用，記適用版本／條件。沒有這類資料不強制要求新建知識庫，也不冒稱本團隊曾發生某種缺陷。

經驗用來產生失效假說與候選情境；由已確認規格支持 Expected。無判準時記待決問題或探索任務，不能從舊 bug 的修法、既有程式或參考產品直接推成新規則。人採納後保留真實決策、適用條件及限制。

方法與深度見 [test-design.md](test-design.md)；跨需求及非需求風險見 [risk-assessment.md](risk-assessment.md)。只深入與本輪品質目標及重大失效有關的方向，保留未測部分與回訪條件。
